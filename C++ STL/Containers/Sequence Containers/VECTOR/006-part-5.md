# Amortized O(1)

`push_back()` is usually constant time.

Occasionally the vector reallocates memory and moves/copies all
elements, making that single insertion O(n). Across many insertions, the
average cost remains amortized **O(1)**.

# Iterator Invalidation Rules

## `push_back()`

-   No reallocation → existing iterators remain valid except `end()`.
-   Reallocation → all iterators, references and pointers become
    invalid.

------------------------------------------------------------------------

## `insert()`

-   Without reallocation → iterators from insertion point onward become
    invalid.
-   With reallocation → all iterators become invalid.

------------------------------------------------------------------------

## `erase()`

-   Erased iterator becomes invalid.
-   Iterators after the erased position become invalid.
-   Iterators before the erased position remain valid.

------------------------------------------------------------------------

## `resize()`

-   Growing may reallocate.
-   Shrinking invalidates iterators to erased elements.

------------------------------------------------------------------------

## `assign()`

All iterators, references and pointers become invalid.

------------------------------------------------------------------------

## `clear()`

All iterators, references and pointers become invalid.

Capacity usually remains unchanged.

------------------------------------------------------------------------

## `swap()`

Iterators continue to refer to the same elements, but those elements now
belong to the other vector.

------------------------------------------------------------------------

# Iterator Invalidation Summary

  Operation       Iterator Status
  --------------- -------------------------------
  `push_back()`   May invalidate all
  `insert()`      May invalidate all
  `erase()`       Erased and following invalid
  `assign()`      All invalid
  `clear()`       All invalid
  `reserve()`     All invalid if reallocation
  `resize()`      May invalidate
  `swap()`        Elements move to other vector

# Best Practices

-   Use `reserve()` when the number of elements is known.
-   Prefer `emplace_back()` for constructing complex objects.
-   Prefer `at()` for safer access.
-   Use range-based `for` loops for readability.
-   Use `const` references when reading elements.
-   Reacquire iterators after any operation that may reallocate.
-   Avoid frequent insertion at the beginning or middle.
-   Use `std::move()` when transferring ownership.

# Common Mistakes

## Accessing Invalid Index

``` cpp
vector<int> v={1,2};

cout<<v[10];
```

Undefined behavior.

Prefer

``` cpp
cout<<v.at(10);
```

------------------------------------------------------------------------

## Forgetting `reserve()`

``` cpp
vector<int> v;

for(int i=0;i<100000;i++)
    v.push_back(i);
```

Better

``` cpp
vector<int> v;
v.reserve(100000);

for(int i=0;i<100000;i++)
    v.push_back(i);
```

------------------------------------------------------------------------

## Using Invalid Iterator

``` cpp
auto it=v.begin();

v.push_back(100);

cout<<*it;
```

May be invalid if reallocation occurred.

# Complete Example

``` cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int main()
{
    vector<int> v;

    v.reserve(10);

    v.push_back(30);
    v.push_back(10);
    v.push_back(20);

    sort(v.begin(),v.end());

    cout<<"Elements : ";

    for(int x:v)
        cout<<x<<" ";

    cout<<"\nFront : "<<v.front();
    cout<<"\nBack : "<<v.back();
    cout<<"\nSize : "<<v.size();
    cout<<"\nCapacity : "<<v.capacity();

    v.erase(v.begin());

    cout<<"\nAfter erase : ";

    for(int x:v)
        cout<<x<<" ";

    return 0;
}
```

Output

``` text
Elements : 10 20 30
Front : 10
Back : 30
Size : 3
Capacity : 10
After erase : 20 30
```

# Interview Questions

### What is the difference between size and capacity?

Current elements vs allocated storage.

------------------------------------------------------------------------

### Why is `push_back()` amortized O(1)?

Because occasional reallocations are spread across many insertions.

------------------------------------------------------------------------

### Does `clear()` release memory?

Usually no.

------------------------------------------------------------------------

### Which container is better for front insertion?

`std::deque`

------------------------------------------------------------------------

### Why is `vector` cache friendly?

Because elements are stored contiguously.

------------------------------------------------------------------------

### When should `reserve()` be used?

When the approximate number of elements is known in advance.

------------------------------------------------------------------------

### Difference between `push_back()` and `emplace_back()`?

`push_back()` inserts an existing object.

`emplace_back()` constructs the object directly.

------------------------------------------------------------------------

### What invalidates iterators?

Reallocation, `assign()`, `clear()`, many `insert()` operations, and
some `erase()` operations.
