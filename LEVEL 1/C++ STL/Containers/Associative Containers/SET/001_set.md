# 1. Introduction

`std::set` is an **ordered associative container** provided by the C++ Standard Template Library (STL).

It stores:

- Unique elements
- In sorted order
- According to a comparison object

Example:

```cpp
#include <iostream>
#include <set>

using namespace std;

int main() {

    set<int> numbers;

    numbers.insert(30);
    numbers.insert(10);
    numbers.insert(20);
    numbers.insert(10);

    for (int x : numbers) {
        cout << x << " ";
    }

    return 0;
}
```

**Output:** 10 20 30

The second `10` is not inserted because a `set` does not allow duplicate elements.

# 6. Template Parameters

The simplified declaration is:

```cpp
template<
    class Key,
    class Compare = less<Key>,
    class Allocator = allocator<Key>
>
class set;
```

### Parameters

| Parameter | Meaning |
|---|---|
| `Key` | Type of elements stored in the set |
| `Compare` | Determines element ordering |
| `Allocator` | Controls memory allocation |

Example:

```cpp

```

Conceptually means:

```text
Key       = int
Compare   = less<int>
```

Therefore:

```text
1 2 3 4 5
```

is the default ordering.

- A `set` stores **values**, not key-value pairs.

**Example:**
```cpp

```

**contains:**
```text

```

**There is no separate:** `key -> value` relationship.

**Compare:**
### `set`
```cpp

```
```text
10

```

### `map`

```text

20 -> Twenty
```

# 8. Ordered Associative Container
- `std::set` is an **ordered associative container**.

**This means:**
```text
Associative
    ↓
Elements are organized for efficient lookup

Ordered
    ↓
Elements are maintained according to a comparator
```

**By default:**
`less<Key>` is used.

Therefore:

```cpp
set<int> s = {30, 10, 20};
```

iterates as:

```text
10 20 30
```

The order is not based on insertion order.

---

# 9. Internal Working

`std::set` requires an ordering relation between elements.

It is typically implemented using a **self-balancing binary search tree**, commonly a **Red-Black Tree**.

Conceptually:

```text
              20
            /    \
          10      40
         /       /  \
        5       30   60
```

The exact internal tree representation is implementation-dependent.

The C++ standard specifies the behavior and complexity requirements of `std::set`; it does not require every implementation to use a Red-Black Tree.

However, Red-Black Trees are a common implementation.

---

# 10. Red-Black Tree Concept

A Red-Black Tree is a self-balancing binary search tree.

It maintains additional balancing information for nodes.

Conceptually, a node may contain:

```text
-------------------------
Value
Left link
Right link
Parent link
Color information
-------------------------
```

The balancing rules prevent the tree from becoming excessively tall.

Therefore operations such as:

```text
Search
Insert
Erase
```

can generally remain:

```text
O(log n)
```

---

# 11. How Uniqueness Works

This is an important concept.

A `set` does not simply ask:

```text
Are the two objects identical using ==?
```

Instead, uniqueness is determined according to the ordering relation.

For two values `a` and `b`, they are considered equivalent when:

```cpp
!comp(a, b) && !comp(b, a)
```

where `comp` is the set's comparator.

For the default:

```cpp
less<int>
```

consider:

```text
10
10
```

Neither is less than the other.

Therefore they are equivalent, so only one is stored.

---

## Important Interview Point

For a `set`, uniqueness is determined by the comparator's ordering, not necessarily by `operator==`.

This becomes very important with custom objects.

---

# 12. Characteristics

`std::set` has these major characteristics:

- Stores unique elements.
- Maintains sorted order.
- Uses a comparison object to define ordering.
- Supports custom comparators.
- Usually implemented with a self-balancing tree.
- Search is O(log n).
- Insertion is O(log n).
- Deletion is O(log n).
- Does not support random indexing.
- Does not provide `operator[]`.
- Provides bidirectional iterators.
- Elements are effectively immutable through normal iterators.
- Supports ordered lookup operations.
- Supports node extraction since C++17.
- Supports `merge()` since C++17.
- Supports `contains()` since C++20.

# 13. Memory Structure

Suppose:

```cpp
set<int> s;

s.insert(20);
s.insert(10);
s.insert(40);
```

Conceptually:

```text
             20
            /  \
          10    40
```

A tree node generally needs information such as:

```text
-------------------------
Element
Left link
Right link
Parent link
Balancing information
-------------------------
```

The exact representation is implementation-specific.

Because each element is usually stored in an individual tree node, a `set` generally has more memory overhead than a contiguous container such as:

```cpp
vector<int>
```

# 15. Iterator Invalidation

One major advantage of node-based associative containers is iterator stability.

In general, inserting elements into a `set` does not invalidate existing iterators or references.

Erasing an element invalidates iterators and references to the erased element.

Example:

```cpp
auto it = s.find(20);

s.insert(50);

// it is still valid if 20 was not erased
```

But:

```cpp
s.erase(it);
```

makes that iterator invalid.

Do not use an iterator after erasing the element it referred to.

# 27. `extract()` — C++17

`extract()` removes a node from the set and returns a node handle.

Example:

```cpp
set<int> s = {
    10,
    20,
    30
};

auto node = s.extract(20);
```

Now:

```text

```

The extracted element is held by:

```cpp
node
```

The node can be inserted into another compatible associative container.

# 28. `merge()` — C++17

`merge()` transfers elements from one set to another.

Example:

```cpp
set<int> a = {
    1,
    2,
    3
};

set<int> b = {
    3,
    4,
    5
};

a.merge(b);
```

Result:

```text
a:
1 2 3 4 5
```

and:

```text
b:
3
```

Why does `3` remain in `b`?

Because `a` already contains `3`.

`set` cannot contain duplicate values.

Therefore:

```text
Destination already contains value
             ↓
Cannot transfer duplicate
             ↓
Element remains in source
```

# 33. `lower_bound()`

Returns an iterator to the first element that is:

```text
>= target
```

Example:

```cpp
set<int> s = {
    10,
    20,
    30,
    40
};

auto it = s.lower_bound(25);

if (it != s.end()) {
    cout << *it;
}
```

Output:

```text
30
```

Because:

```text
10 < 25
20 < 25
30 >= 25
```

Therefore:

```text
30
```

is returned.

---

## Example with exact value

```cpp
auto it = s.lower_bound(20);
```

Returns:

```text
20
```

because:

```text
20 >= 20
```

---

## If no element satisfies the condition

```cpp
auto it = s.lower_bound(100);
```

If all elements are less than `100`:

```cpp
it == s.end()
```

Never dereference it without checking.

# 35. `equal_range()`

Returns:

```text

```


```text

20 if it exists

    ↓
first element greater than 20
```

If `20` does not exist, both iterators identify the insertion position for `20`.

# 42. Custom Objects

A `set` can store custom objects.

Example:

```cpp
class Student {

public:

    int id;
    string name;

    bool operator<(const Student& other) const {
        return id < other.id;
    }
};
```

Then:

```cpp
set<Student> students;
```

Example:

```cpp
students.insert({101, "Amit"});
students.insert({102, "Rahul"});
students.insert({103, "Deep"});
```

The ordering is based on:

```cpp
id
```

because the comparator compares:

```cpp
id < other.id
```

---

# Important Custom Object Concept

Suppose:

```cpp
Student a{1, "Amit"};
Student b{1, "Rahul"};
```

The comparator:

```cpp
return id < other.id;
```

considers them equivalent because:

```text
a.id < b.id -> false
b.id < a.id -> false
```

Therefore only one of them can exist in the set.

This demonstrates why set uniqueness depends on the comparator.

# 43. `std::pair` with `set`

You can store pairs:

```cpp
set<pair<int, string>> s;
```

Example:

```cpp
s.insert({2, "Two"});
s.insert({1, "One"});
s.insert({3, "Three"});
```

Output:

```text
1 One
2 Two
3 Three
```

`std::pair` has lexicographical comparison.

It first compares:

```text
first
```

If the first values are equal, it compares:

```text
second
```

Example:

```cpp
set<pair<int, string>> s;

s.insert({1, "B"});
s.insert({1, "A"});
```

Output:

```text
1 A
1 B
```

because:

```text
first values equal
        ↓
compare second
        ↓
"A" < "B"
```

# 45. Why Set Elements Cannot Be Modified

```cpp
set<int> s = {
    10,
    20,
    30
};
```

You might try:

```cpp
auto it = s.find(20);

*it = 50;
```

This is not allowed.

Why?

Because changing:

```text
20 -> 50
```

could break the ordering of the tree.

The set's elements are treated as const through ordinary iterators.

Conceptually:

```cpp
set<int>::iterator
```

behaves like an iterator to:

```cpp
const int
```

for the element.

---

# 46. Changing an Element

Suppose you want:

```text
20
```

to become:

```text
50
```

You cannot directly modify it.

### Traditional method

Erase and insert:

```cpp
auto it = s.find(20);

if (it != s.end()) {
    s.erase(it);
    s.insert(50);
}
```

---

## C++17 Node Handle Method

```cpp
auto node = s.extract(20);

if (!node.empty()) {

    node.value() = 50;

    s.insert(std::move(node));
}
```

This can modify the extracted value without destroying and reconstructing the node in the same way as a simple erase/insert approach.

---

# 47. Iterator and Reference Rules

Important rules:

### Insertion

Inserting a new element generally does not invalidate existing iterators or references.

```cpp
auto it = s.find(20);

s.insert(50);

cout << *it;
```

The iterator remains valid if `20` was not erased.

---

### Erasing one element

```cpp
auto it = s.find(20);

s.erase(it);
```

Now:

```cpp
it
```

is invalid.

Do not use it afterward.

---

### Clearing

```cpp
s.clear();
```

All iterators and references to elements become invalid because all elements are erased.

# 50. `set` vs `vector`

| Feature | `set` | `vector` |
|---|---|---|
| Storage | Tree nodes | Contiguous memory |
| Sorted automatically | Yes | No |
| Duplicate values | No | Yes |
| Random access | No | Yes |
| `operator[]` | No | Yes |
| Search | O(log n) | O(n), unless sorted + binary search |
| Insert | O(log n) | Depends on position |
| Erase | O(log n) by key | O(n) depending on position |
| Memory overhead | Higher | Lower |
| Cache locality | Usually poorer | Usually better |

Use `vector` when:

- You need random access.
- Data is mostly sequential.
- Cache locality is important.
- You do not require automatic ordered uniqueness.

Use `set` when:

- You need unique values.
- You need automatic ordering.
- You frequently insert/delete/search dynamically.

# 51. `set` vs `vector + sort + unique`

Another common design is:

```cpp
vector<int> v;
```

followed by:

```cpp
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());
```

This can be very efficient when you receive a large batch of data and do not need the data to remain dynamically ordered during insertion.

### `set`

```text
Insert one item
      ↓
Immediately ordered
      ↓
Duplicates rejected
```

### `vector + sort + unique`

```text
Collect data
      ↓
Sort once
      ↓
Remove duplicates
```

For batch processing, a vector can sometimes have better cache behavior and lower memory overhead.

# 52. Common Mistakes

## Mistake 1: Expecting insertion order

```cpp
set<int> s;

s.insert(30);
s.insert(10);
s.insert(20);
```

Do not expect:

```text
30 10 20
```

Iteration follows the comparator's order:

```text
10 20 30
```

---

## Mistake 2: Trying to use indexing

This is invalid:

```cpp
cout << s[0];
```

A `set` does not provide random indexing.

---

## Mistake 3: Trying to modify an element

Invalid:

```cpp
auto it = s.find(20);
*it = 50;
```

Use erase/insert or C++17 node handles.

---

## Mistake 4: Dereferencing `end()`

Invalid:

```cpp
cout << *s.end();
```

`end()` does not point to an element.

---

## Mistake 5: Using `find()` without checking

Wrong:

```cpp
cout << *s.find(100);
```

If `100` does not exist, `find()` returns:

```cpp
s.end()
```

Correct:

```cpp
auto it = s.find(100);

if (it != s.end()) {
    cout << *it;
}
```

---

## Mistake 6: Assuming `count()` can return more than 1

For:

```cpp
set<int>
```

the result is only:

```text
0 or 1
```

For `multiset`, it can be greater than 1.

---

## Mistake 7: Incorrect custom comparator

A comparator used by an ordered container must provide a valid **strict weak ordering**.

Do not write arbitrary comparison logic.

A broken comparator can cause incorrect behavior in the ordered container.

# Example 6 — Erase While Iterating

A safe pattern is:

```cpp
for (auto it = s.begin(); it != s.end(); ) {

    if (*it % 2 == 0) {
        it = s.erase(it);
    }
    else {
        ++it;
    }
}
```

`erase(it)` returns an iterator to the element following the erased element.

Result: all even numbers are removed.

---

# Example 7 — Range Query

Suppose:

```cpp
set<int> s = {
    10,
    20,
    30,
    40,
    50,
    60
};
```

Find values in the range:

```text
30 <= x < 60
```

Use:

```cpp
auto first = s.lower_bound(30);
auto last = s.lower_bound(60);

for (auto it = first; it != last; ++it) {
    cout << *it << " ";
}
```

Output:

```text
30 40 50
```

# Example 8 — Complete Program

```cpp
#include <iostream>
#include <set>

using namespace std;

int main() {

    set<int> numbers;

    // Insert
    numbers.insert(30);
    numbers.insert(10);
    numbers.insert(20);
    numbers.insert(40);
    numbers.insert(10);

    cout << "Elements:\n";

    for (int x : numbers) {
        cout << x << " ";
    }

    cout << "\n";

    // Size
    cout << "Size: "
         << numbers.size()
         << "\n";

    // Find
    if (numbers.find(20) != numbers.end()) {
        cout << "20 found\n";
    }

    // Contains
    if (numbers.contains(30)) {
        cout << "30 exists\n";
    }

    // Lower bound
    auto it = numbers.lower_bound(25);

    if (it != numbers.end()) {
        cout << "Lower bound of 25: "
             << *it << "\n";
    }

    // Erase
    numbers.erase(20);

    cout << "After erase:\n";

    for (int x : numbers) {
        cout << x << " ";
    }

    return 0;
}
```

Possible output:

```text
Elements:
10 20 30 40

Size: 4
20 found
30 exists
Lower bound of 25: 30
After erase:
10 30 40
```

# 54. Interview Questions

## Q1. What is `std::set`?

`std::set` is an ordered associative STL container that stores unique elements according to a comparison object.

---

## Q2. Does a set allow duplicates?

No.

```cpp
set<int> s;

s.insert(10);
s.insert(10);
```

Only one `10` exists.

---

## Q3. Is `set` sorted?

Yes.

By default, elements are sorted in ascending order.

---

## Q4. What is the default comparator?

Conceptually:

```cpp
std::less<Key>
```

---

## Q5. What is the typical internal implementation of `set`?

A self-balancing binary search tree, commonly a Red-Black Tree.

The C++ standard does not mandate one particular tree implementation.

---

## Q6. What is the complexity of `find()`?

```text
O(log n)
```

---

## Q7. What is the complexity of insertion?

Typically:

```text
O(log n)
```

---

## Q8. Why does set not provide `operator[]`?

Because `set` is not a key-to-value or random-access container.

It stores values in an ordered tree.

---

## Q9. Why can't set elements be modified directly?

Changing an element could break the ordering invariant.

Therefore the elements are treated as const through normal iterators.

---

## Q10. How do you modify an element?

Traditional:

```cpp
auto it = s.find(oldValue);

if (it != s.end()) {
    s.erase(it);
    s.insert(newValue);
}
```

C++17:

```cpp
auto node = s.extract(oldValue);

node.value() = newValue;

s.insert(std::move(node));
```

---

## Q11. What is the difference between `find()` and `count()`?

`find()` returns an iterator:

```cpp
auto it = s.find(20);
```

`count()` returns the number of matching elements.

For `set`:

```text
0 or 1
```

---

## Q12. What is `contains()`?

C++20:

```cpp
s.contains(value)
```

returns a boolean indicating whether the value exists.

---

## Q13. What is `lower_bound()`?

First element satisfying:

```text
element >= target
```

---

## Q14. What is `upper_bound()`?

First element satisfying:

```text
element > target
```

---

## Q15. What is the difference between `set` and `multiset`?

```text
set
    -> unique elements

multiset
    -> duplicate elements allowed
```

Both maintain sorted order.

---

## Q16. What is the difference between `set` and `unordered_set`?

```text
set
    -> ordered
    -> O(log n)

unordered_set
    -> unordered
    -> O(1) average
```

---

## Q17. How does set determine whether two custom objects are duplicates?

Using the comparator.

Two objects are considered equivalent when:

```cpp
!comp(a, b) && !comp(b, a)
```

---

## Q18. Can the set store custom objects?

Yes, provided the set has a valid comparison relation.

Example:

```cpp
set<Student> students;
```

with an appropriate comparator.

---

## Q19. Can a set use descending order?

Yes.

```cpp
set<int, greater<int>> s;
```

---

## Q20. What is `extract()`?

C++17 node-handle functionality that removes a node without destroying the contained object and returns ownership of that node through a node handle.

---

## Q21. What is `merge()`?

C++17 operation that transfers compatible nodes from one associative container to another.

Duplicate elements that cannot be inserted remain in the source container.

---

## Q22. Does insertion invalidate set iterators?

In general, no. Existing iterators and references remain valid when another element is inserted.

Erasing an element invalidates iterators/references to that erased element.

---

## Q23. Why is `set::find()` better than `std::find()` for a set?

`set::find()` uses the set's tree ordering and provides:

```text
O(log n)
```

search.

A generic:

```cpp
std::find(s.begin(), s.end(), value)
```

performs a linear scan:

```text
O(n)
```

So for a `set`, prefer:

```cpp
s.find(value)
```

for key/value lookup.
