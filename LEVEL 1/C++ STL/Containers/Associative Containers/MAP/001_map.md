# 1. Introduction
- It stores data as **key-value pairs**. Every key is **unique**.
- Elements are maintained in **sorted order according to the key**.
- By default, keys are sorted in ascending order.
- Internally, `std::map` is typically implemented using a **Red-Black Tree**.
- Searching, insertion, and deletion generally take **O(log n)** time.
- Each element is represented as a `std::pair<const Key, T>`.

### Example

```cpp
#include <iostream>
#include <map>
using namespace std;

int main() {

    map<int, string> students;

    students.insert({101, "Amit"});
    students.insert({102, "Rahul"});
    students.insert({103, "Deep"});

    for (const auto& item : students) {
        cout << item.first << " " << item.second << endl;
    }
}
```

**Output:**  
101 Amit  
102 Rahul  
103 Deep  

### Important
```cpp
map<int, string>
```

**means:**
- Key   -> int
- Value -> string

**For example:**
101 -> "Amit"
102 -> "Rahul"
103 -> "Deep"

# 7. Internal Working

`std::map` is an **ordered associative container**.

It is typically implemented using a **self-balancing binary search tree**, commonly a **Red-Black Tree**.

Conceptually:

```text
              20
            /    \
          10      40
         /       /  \
        5       30   60
```

The exact tree shape is implementation-dependent.

The important idea is:

```text
Key comparison
      ↓
Binary search tree structure
      ↓
Self balancing
      ↓
O(log n) operations
```

### Example

```cpp
map<int, string> m;

m[20] = "Twenty";
m[10] = "Ten";
m[40] = "Forty";
```

The keys are maintained in sorted order:

```text
10 -> Ten
20 -> Twenty
40 -> Forty
```

### Why balancing is important

Without balancing, a tree could become similar to:

```text
10
  \
   20
     \
      30
        \
         40
```

This could approach:

```text
O(n)
```

for searching.

A balanced tree keeps the height approximately logarithmic, providing:

```text
O(log n)
```

search, insertion, and deletion.

> The C++ standard specifies the container's behavior and complexity requirements, not a mandatory specific internal implementation. A Red-Black Tree is the common implementation.

# 8. Characteristics

`std::map` has the following important characteristics:

- Stores key-value pairs.
- Keys are unique.
- Keys are sorted.
- Default sorting is ascending.
- Supports custom comparators.
- Does not provide random access by integer index.
- Supports bidirectional iterators.
- Searching is generally O(log n).
- Insertion is generally O(log n).
- Erasing an element is generally O(log n).
- Dynamic size.
- Each key maps to one value.
- `operator[]` can create a new element if the key does not exist.
- `at()` accesses an existing key and throws if the key is missing.

---

# 9. Memory Layout

**Suppose:**
```cpp
map<int, string> m;

m[20] = "A";
m[10] = "B";
m[40] = "C";
```

Conceptually:

```text
             20 -> "A"
            /          \
     10 -> "B"       40 -> "C"
```

A tree node generally needs information such as:

```text
--------------------------------
Key
Value
Left child pointer/reference
Right child pointer/reference
Parent pointer/reference
Balancing information
--------------------------------
```

The exact node representation is implementation-specific.

### Important

A map usually requires more memory per element than a contiguous container such as:

```cpp
vector<pair<int, string>>
```

because tree nodes require links and balancing metadata.

# 10. Time Complexity

| Operation | Complexity |
|---|---:|
| `insert()` | O(log n) |
| `emplace()` | O(log n) |
| `try_emplace()` | O(log n) |
| `insert_or_assign()` | O(log n) |
| `erase(key)` | O(log n) |
| `erase(iterator)` | Amortized constant for the erase operation itself, plus any required rebalancing; exact implementation details are hidden |
| `find()` | O(log n) |
| `count()` | O(log n) |
| `contains()` | O(log n) |
| `lower_bound()` | O(log n) |
| `upper_bound()` | O(log n) |
| `equal_range()` | O(log n) |
| `size()` | O(1) |
| `empty()` | O(1) |
| `clear()` | O(n) |
| `begin()` | O(1) |
| `end()` | O(1) |

### Important distinction

For `std::map`:

```text
Search      -> O(log n)
Insertion   -> O(log n)
Deletion    -> O(log n)
```

These are the major performance characteristics to remember.

# 15. Element Access

`std::map` provides two major direct access functions:

```cpp
operator[]
at()
```

---

# 15.1 `operator[]`

Syntax:

```cpp
m[key]
```

Example:

```cpp
map<int, string> students;

students[101] = "Amit";
students[102] = "Rahul";

cout << students[101];
```

Output:

```text
Amit
```

### Very important behavior

If the key does not exist:

```cpp
cout << students[999];
```

`operator[]` inserts the key with a **value-initialized mapped value** and then returns a reference to that value.

For example:

```cpp
map<int, string> m;

cout << m[10];
```

For `string`, the inserted value is:

```text
""
```

After this:

```text
10 -> ""
```

Therefore:

```cpp
m[10]
```

is not a pure lookup operation.

---

# 15.2 `at()`

```cpp
cout << m.at(101);
```

If the key exists, it returns a reference to the mapped value.

If the key does not exist:

```cpp
m.at(999);
```

it throws:

```cpp
std::out_of_range
```

### Example

```cpp
map<int, string> m = {
    {1, "A"},
    {2, "B"}
};

try {
    cout << m.at(3);
}
catch (const out_of_range& e) {
    cout << "Key not found";
}
```

---

# 15.3 `operator[]` vs `at()`

| Feature | `operator[]` | `at()` |
|---|---|---|
| Existing key | Returns value reference | Returns value reference |
| Missing key | Inserts key | Throws `out_of_range` |
| Good for lookup without insertion | No | Yes |
| Can modify value | Yes | Yes |
| Complexity | O(log n) | O(log n) |

### Rule

Use:

```cpp
m[key]
```

when you intentionally want insertion/update behavior.

Use:

```cpp
m.at(key)
```

when the key should already exist and you want bounds checking.

Use:

```cpp
m.find(key)
```

when you want to check existence without inserting.

# 16. Modifiers

## 16.1 `insert()`

Inserts a key-value pair.

```cpp
m.insert({101, "Amit"});
```

Example:

```cpp
map<int, string> m;

auto result = m.insert({101, "Amit"});

if (result.second) {
    cout << "Inserted";
}
```

`insert()` returns a pair containing:

```text
iterator
bool
```

The `bool` indicates whether insertion took place.

---

## 16.2 Duplicate Key with `insert()`

```cpp
map<int, string> m;

m.insert({1, "A"});
m.insert({1, "B"});
```

The second insertion does not replace the existing value.

Result:

```text
1 -> A
```

The key must remain unique.

---

## 16.3 Insert with Hint

```cpp
auto hint = m.begin();

m.insert(hint, {5, "Five"});
```

A hint can help performance when it is appropriate, but it does not force a particular position.

---

## 16.4 Range Insert

```cpp
vector<pair<int, string>> v = {
    {1, "A"},
    {2, "B"},
    {3, "C"}
};

m.insert(v.begin(), v.end());
```

---

## 16.5 `emplace()`

Constructs the map element in place.

```cpp
m.emplace(101, "Amit");
```

This can avoid an unnecessary temporary object in some cases.

---

## 16.6 `try_emplace()` — C++17

```cpp
m.try_emplace(101, "Amit");
```

Important advantage:

- If the key already exists, the mapped value is not constructed from the supplied arguments.
- Useful when constructing expensive mapped objects.

Example:

```cpp
map<int, string> m;

m.try_emplace(1, "Amit");
m.try_emplace(1, "Rahul");
```

Result:

```text
1 -> Amit
```

The second call does not replace the existing value.

---

## 16.7 `insert_or_assign()` — C++17

```cpp
m.insert_or_assign(1, "Rahul");
```

Behavior:

- If key does not exist → inserts it.
- If key exists → replaces/assigns its mapped value.

Example:

```cpp
map<int, string> m;

m.insert_or_assign(1, "Amit");
m.insert_or_assign(1, "Rahul");
```

Result:

```text
1 -> Rahul
```

---

## 16.8 `erase(key)`

```cpp
m.erase(101);
```

Removes the element whose key is `101`.

For `std::map`, the return value is the number of erased elements:

```text
0 -> key did not exist
1 -> key existed and was erased
```

---

## 16.9 `erase(iterator)`

```cpp
auto it = m.find(101);

if (it != m.end()) {
    m.erase(it);
}
```

---

## 16.10 `erase(range)`

```cpp
m.erase(m.begin(), m.find(103));
```

This erases elements from `begin()` up to, but not including, the element returned by `find(103)`.

---

## 16.11 `clear()`

```cpp
m.clear();
```

Removes all elements.

After:

```cpp
m.clear();
```

the map is empty.

---

## 16.12 `swap()`

```cpp
m1.swap(m2);
```

Swaps the contents of two maps.

You can also write:

```cpp
swap(m1, m2);
```

# 17. Lookup Functions

## 17.1 `find()`

Searches for a key.

```cpp
auto it = m.find(101);
```

If found:

```cpp
it != m.end()
```

If not found:

```cpp
it == m.end()
```

Example:

```cpp
if (auto it = m.find(101); it != m.end()) {
    cout << it->second;
}
```

---

## 17.2 `count()`

For `std::map`, a key can occur at most once.

```cpp
cout << m.count(101);
```

Returns:

```text
0 -> key does not exist
1 -> key exists
```

---

## 17.3 `contains()` — C++20

```cpp
if (m.contains(101)) {
    cout << "Found";
}
```

Returns `true` or `false`.

This is often cleaner than:

```cpp
m.find(101) != m.end()
```

---

# 17.4 `lower_bound()`

Returns an iterator to the first key that is **not less than** the specified key.

In simple terms:

```text
first key >= target
```

Example:

```cpp
map<int, string> m = {
    {10, "A"},
    {20, "B"},
    {30, "C"},
    {40, "D"}
};

auto it = m.lower_bound(25);

if (it != m.end())
    cout << it->first;
```

Output:

```text
30
```

---

# 17.5 `upper_bound()`

Returns an iterator to the first key that is **greater than** the specified key.

In simple terms:

```text
first key > target
```

Example:

```cpp
auto it = m.upper_bound(20);

if (it != m.end())
    cout << it->first;
```

Output:

```text
30
```

---

# 17.6 `equal_range()`

Returns both:

```text
lower_bound()
upper_bound()
```

Example:

```cpp
auto range = m.equal_range(20);

cout << range.first->first;
```

For a `map`, because keys are unique, the range contains either:

- the single matching element, or
- an empty range if the key does not exist.

A custom type can also be used as a key, but the map needs a valid ordering comparator.


The comparator determines how `Student` keys are ordered.

# 24. Node Handles: `extract()` — C++17

`extract()` removes a node from the map and returns a node handle.

Example:

```cpp
map<int, string> m = {
    {1, "A"},
    {2, "B"},
    {3, "C"}
};

auto node = m.extract(2);
```

Now:

```text
m:
1 -> A
3 -> C
```

The extracted node is held by:

```cpp
node
```

The node can be inserted into another compatible associative container.

---

## Changing a Key with `extract()`

Normally, map keys cannot be modified directly.

This is not allowed:

```cpp
it->first = 100;   // Error
```

But C++17 node handles allow:

```cpp
auto node = m.extract(2);

node.key() = 200;

m.insert(std::move(node));
```

This changes the key while preserving the node.

# 25. `merge()` — C++17

`merge()` transfers nodes from one map to another.

Example:

```cpp
map<int, string> a = {
    {1, "A"},
    {2, "B"},
    {3, "C"}
};

map<int, string> b = {
    {3, "X"},
    {4, "D"},
    {5, "E"}
};

a.merge(b);
```

Result:

```text
a:
1 -> A
2 -> B
3 -> C
4 -> D
5 -> E
```

And:

```text
b:
3 -> X
```

### Why does key `3` remain in `b`?

Because `a` already contains key `3`.

`merge()` cannot overwrite an existing key.

Therefore:

```text
Destination already has key
        ↓
Node is not transferred
        ↓
Node remains in source
```

# 26. Comparison Operators

Maps can be compared.

Depending on the C++ standard version, relational comparison support is provided through the standard comparison facilities.

Common equality comparison:

```cpp
if (m1 == m2) {
    cout << "Equal";
}
```

The comparison considers the map's elements.

For modern C++, the relational ordering is specified through the standard comparison machinery rather than relying on deprecated non-member relational operators.

# 27. `operator[]` vs `at()`

This is one of the most important interview topics.

### `operator[]`

```cpp
m[10]
```

If `10` does not exist:

```text
10 -> default value
```

is inserted.

### `at()`

```cpp
m.at(10)
```

If `10` does not exist:

```text
std::out_of_range
```

is thrown.

### Example

```cpp
map<int, string> m;

m[1] = "A";

cout << m[2];
```

Now map contains:

```text
1 -> A
2 -> ""
```

But:

```cpp
m.at(3);
```

throws because key `3` does not exist.

---

# 28. `insert()` vs `emplace()` vs `try_emplace()`

## `insert()`

```cpp
m.insert({1, "A"});
```

Good when you already have a key-value pair.

---

## `emplace()`

```cpp
m.emplace(1, "A");
```

Constructs the element in place.

---

## `try_emplace()` — C++17

```cpp
m.try_emplace(1, "A");
```

Useful when the mapped value may be expensive to construct.

If the key already exists, the mapped value is not constructed from the supplied arguments.

### Summary

```text
insert
   ↓
Insert an existing pair/object

emplace
   ↓
Construct map element in place

try_emplace
   ↓
Construct mapped value only when insertion happens
```

---

# 29. `insert_or_assign()` — C++17

Use this when you want:

```text
Insert if missing
Update if existing
```

Example:

```cpp
map<int, string> m;

m.insert_or_assign(1, "A");
m.insert_or_assign(1, "B");
```

Final result:

```text
1 -> B
```

Compare:

```cpp
m.insert({1, "B"});
```

which would not replace the existing value.

# 30. Complete Basic Example

```cpp
#include <iostream>
#include <map>
#include <string>

using namespace std;

int main() {

    map<int, string> students;

    students.insert({101, "Amit"});
    students.insert({102, "Rahul"});
    students.insert({103, "Deep"});
    students.insert({101, "Other"});

    cout << "Students:\n";

    for (const auto& item : students) {
        cout << item.first << " -> "
             << item.second << endl;
    }

    cout << "\nSize: "
         << students.size() << endl;

    if (students.find(102) != students.end()) {
        cout << "Student 102 found\n";
    }

    students.erase(102);

    cout << "\nAfter erase:\n";

    for (const auto& item : students) {
        cout << item.first << " -> "
             << item.second << endl;
    }

    return 0;
}
```

Output:

```text
Students:
101 -> Amit
102 -> Rahul
103 -> Deep

Size: 3
Student 102 found

After erase:
101 -> Amit
103 -> Deep
```

# 40. Advantages

- Stores key-value pairs.
- Keys are automatically sorted.
- Keys are unique.
- Fast lookup.
- Fast insertion.
- Fast deletion.
- No manual sorting required.
- Supports custom comparators.
- Supports ordered operations such as:
  - `lower_bound()`
  - `upper_bound()`
  - `equal_range()`
- Supports node extraction and merging from C++17.
- Useful when deterministic sorted traversal is required.

---

# 41. Disadvantages

- No random access by index.
- O(log n) lookup is usually slower than average O(1) lookup of `unordered_map`.
- More memory overhead than contiguous containers.
- Tree nodes have poorer cache locality than contiguous data structures.
- Keys must have a valid ordering relation.
- Duplicate keys are not supported.
- `operator[]` can unexpectedly insert a key during lookup.

# 42. Common Mistakes

## Mistake 1: Expecting duplicate keys

```cpp
m[1] = "A";
m[1] = "B";
```

This does not create two entries.

It updates:

```text
1 -> B
```

---

## Mistake 2: Using `operator[]` only to check existence

Bad if insertion is unwanted:

```cpp
if (m[100] == "A") {
}
```

If key `100` does not exist, it may be inserted.

Prefer:

```cpp
if (m.find(100) != m.end()) {
}
```

or C++20:

```cpp
if (m.contains(100)) {
}
```

---

## Mistake 3: Modifying a map key through an iterator

This is invalid:

```cpp
it->first = 200;
```

The key is effectively const:

```cpp
pair<const Key, T>
```

Use `extract()` in C++17 if you need to change a key.

---

## Mistake 4: Dereferencing `end()`

Do not do:

```cpp
cout << m.end()->first;
```

`end()` is not an element.

Correct:

```cpp
auto it = m.find(10);

if (it != m.end()) {
    cout << it->first;
}
```

---

## Mistake 5: Assuming `find()` returns a value

It returns an iterator:

```cpp
auto it = m.find(10);
```

Use:

```cpp
it->first
it->second
```

after checking that it is not `end()`.

# 43. Common Interview Questions

## Q1. What is `std::map`?

`std::map` is an ordered associative container that stores unique keys mapped to values.

---

## Q2. Does `map` allow duplicate keys?

No.

```cpp
map<int, string>
```

can contain only one value for each key.

---

## Q3. Is `map` sorted?

Yes.

By default, keys are sorted in ascending order according to `std::less<Key>`.

---

## Q4. How does `map` maintain sorted order?

It uses an ordered tree structure. Common implementations use a self-balancing Red-Black Tree.

---

## Q5. What is the complexity of `find()`?

```text
O(log n)
```

for `std::map`.

---

## Q6. What is the complexity of insertion?

Typically:

```text
O(log n)
```

---

## Q7. What happens when inserting a duplicate key?

The new element is not inserted by normal `insert()`/`emplace()` operations.

Example:

```cpp
m.insert({1, "A"});
m.insert({1, "B"});
```

Result:

```text
1 -> A
```

---

## Q8. How do you update an existing value?

Using:

```cpp
m[key] = newValue;
```

or:

```cpp
m.insert_or_assign(key, newValue);
```

---

## Q9. Difference between `insert()` and `insert_or_assign()`?

`insert()`:

```text
Does not replace existing value.
```

`insert_or_assign()`:

```text
Inserts if missing.
Assigns if existing.
```

---

## Q10. Difference between `operator[]` and `at()`?

```text
operator[]
    ↓
Inserts missing key with value-initialized mapped value.

at()
    ↓
Throws std::out_of_range if key is missing.
```

---

## Q11. Difference between `find()` and `count()`?

`find()`:

```cpp
auto it = m.find(key);
```

returns an iterator.

`count()`:

```cpp
m.count(key);
```

returns `0` or `1` for `std::map`.

---

## Q12. What is `contains()`?

C++20 provides:

```cpp
m.contains(key)
```

It returns:

```text
true / false
```

without inserting a missing key.

---

## Q13. Why can't a map key be modified directly?

Because changing a key could violate the ordering structure.

Map elements have type:

```cpp
pair<const Key, T>
```

The key is therefore not modifiable through an ordinary iterator.

---

## Q14. How can you change a key in C++17?

Use:

```cpp
auto node = m.extract(oldKey);

node.key() = newKey;

m.insert(std::move(node));
```

---

## Q15. What is `lower_bound()`?

It returns the first element whose key is:

```text
>= target
```

---

## Q16. What is `upper_bound()`?

It returns the first element whose key is:

```text
> target
```

---

## Q17. Why use `map` instead of `unordered_map`?

Use `map` when you need:

- Sorted keys.
- Ordered iteration.
- `lower_bound()`.
- `upper_bound()`.
- Predictable O(log n) tree-based operations.

---

## Q18. Why use `unordered_map` instead of `map`?

Use `unordered_map` when:

- Key ordering is unnecessary.
- Average O(1) lookup is desirable.
- Hashing is appropriate for the key type.

---

## Q19. What is `multimap`?

`multimap` is an ordered associative container that allows multiple elements with the same key.

Example:

```cpp
multimap<int, string> m;

m.insert({1, "A"});
m.insert({1, "B"});
m.insert({1, "C"});
```

All three elements can exist.

---

## Q20. What is `try_emplace()`?

`try_emplace()` was introduced in C++17.

It inserts only when the key does not already exist and avoids constructing the mapped value from the supplied arguments when insertion does not happen.
