# C++ `std::vector` --- Part 2

# Element Access, Capacity & Memory Management

------------------------------------------------------------------------

# Element Access

`std::vector` provides several ways to access elements.

  Function       Bounds Checked   Complexity
  -------------- ---------------- ------------
  `operator[]`   No               O(1)
  `at()`         Yes              O(1)
  `front()`      No               O(1)
  `back()`       No               O(1)
  `data()`       No               O(1)

------------------------------------------------------------------------

## `operator[]`

Returns the element at the specified index.

``` cpp
vector<int> v={10,20,30};

cout<<v[1];
```

Output

``` text
20
```

-   Very fast.
-   Does **not** check bounds.
-   Accessing an invalid index results in **undefined behavior**.

------------------------------------------------------------------------

## `at()`

``` cpp
vector<int> v={10,20,30};

cout<<v.at(2);
```

Output

``` text
30
```

If the index is invalid:

``` cpp
cout<<v.at(5);
```

Throws

``` text
std::out_of_range
```

Use `try`/`catch` if needed.

------------------------------------------------------------------------

## `front()`

Returns the first element.

``` cpp
vector<int> v={10,20,30};

cout<<v.front();
```

Output

``` text
10
```

------------------------------------------------------------------------

## `back()`

Returns the last element.

``` cpp
cout<<v.back();
```

Output

``` text
30
```

------------------------------------------------------------------------

## `data()`

Returns a pointer to the first element.

``` cpp
vector<int> v={10,20,30};

int* p=v.data();

cout<<p[0];
cout<<p[1];
```

Output

``` text
10
20
```

Useful when calling C APIs expecting arrays.

------------------------------------------------------------------------

# Modifying Through References

``` cpp
vector<int> v={10,20,30};

v.front()=100;
v.back()=500;
```

Result

``` text
100 20 500
```

------------------------------------------------------------------------

# Capacity Functions

Capacity refers to allocated storage, not just stored elements.

------------------------------------------------------------------------

## `size()`

Returns the current number of elements.

``` cpp
vector<int> v={1,2,3};

cout<<v.size();
```

Output

``` text
3
```

Complexity: **O(1)**

------------------------------------------------------------------------

## `capacity()`

Returns allocated storage.

``` cpp
vector<int> v;

cout<<v.capacity();
```

Initially (implementation-dependent, commonly)

``` text
0
```

Example

``` cpp
v.push_back(1);
v.push_back(2);
v.push_back(3);

cout<<v.capacity();
```

Possible output

``` text
4
```

The exact value depends on the implementation.

------------------------------------------------------------------------

## `empty()`

Checks whether the vector contains elements.

``` cpp
vector<int> v;

cout<<v.empty();
```

Output

``` text
1
```

or

``` text
true
```

------------------------------------------------------------------------

## `max_size()`

Returns the maximum number of elements the vector could theoretically
hold.

``` cpp
cout<<v.max_size();
```

Depends on:

-   Allocator
-   Platform
-   Available address space

------------------------------------------------------------------------

## `resize()`

Changes the logical size.

Increase

``` cpp
vector<int> v={1,2,3};

v.resize(5);
```

Output

``` text
1 2 3 0 0
```

Increase with value

``` cpp
v.resize(7,100);
```

Output

``` text
1 2 3 0 0 100 100
```

Decrease

``` cpp
v.resize(2);
```

Output

``` text
1 2
```

Complexity: O(n) when elements are added or removed.

------------------------------------------------------------------------

## `reserve()`

Allocates capacity without changing size.

``` cpp
vector<int> v;

v.reserve(100);
```

Result

``` text
Size = 0
Capacity >= 100
```

Benefits:

-   Fewer reallocations
-   Better performance
-   Iterator stability until capacity is exceeded

------------------------------------------------------------------------

### Why Use `reserve()`?

Without reserve

``` cpp
for(int i=0;i<1000;i++)
    v.push_back(i);
```

Multiple reallocations occur.

With reserve

``` cpp
vector<int> v;

v.reserve(1000);

for(int i=0;i<1000;i++)
    v.push_back(i);
```

Normally only one allocation is needed.

------------------------------------------------------------------------

## `shrink_to_fit()`

Requests removal of unused capacity.

``` cpp
vector<int> v(100);

v.resize(10);

v.shrink_to_fit();
```

Important:

-   Non-binding request.
-   The implementation may ignore it.

------------------------------------------------------------------------

# Memory Management

A vector owns dynamically allocated memory.

Conceptually

``` text
begin ---------------- end -------- end_of_storage
```

Unused capacity exists between `end` and `end_of_storage`.

------------------------------------------------------------------------

## Reallocation

Occurs when

``` text
size == capacity
```

Steps:

1.  Allocate larger block.
2.  Move or copy elements.
3.  Destroy old elements.
4.  Free old memory.
5.  Update internal pointers.

------------------------------------------------------------------------

### Example

Capacity

``` text
4
```

Memory

``` text
---------------------
|10|20|30|40|
---------------------
```

Insert

``` cpp
v.push_back(50);
```

New memory

``` text
------------------------------------------
|10|20|30|40|50| | | |
------------------------------------------
```

------------------------------------------------------------------------

## Growth Strategy

The standard does not define the growth factor.

Typical implementations grow approximately

``` text
1
↓

2
↓

4
↓

8
↓

16
```

Other implementations may use different strategies.

------------------------------------------------------------------------

# Iterator, Pointer and Reference Invalidation

After reallocation

``` cpp
vector<int> v={1,2,3};

int* p=&v[0];

v.push_back(4);
```

If reallocation occurred

``` text
p becomes invalid
```

Always reacquire pointers/iterators after possible reallocation.

------------------------------------------------------------------------

# Memory Efficiency

Unused capacity allows future insertions without allocating memory every
time.

Trade-off:

-   Slightly more memory
-   Better insertion performance

------------------------------------------------------------------------

# `clear()` vs `resize(0)`

``` cpp
v.clear();
```

or

``` cpp
v.resize(0);
```

Both remove all elements.

Capacity is typically unchanged.

------------------------------------------------------------------------

# Freeing Memory Completely

``` cpp
vector<int>().swap(v);
```

or

``` cpp
v = {};
```

Swapping with an empty vector commonly releases memory.

------------------------------------------------------------------------

# Time Complexity

  Function                               Complexity
  ------------------- -----------------------------
  `operator[]`                                 O(1)
  `at()`                                       O(1)
  `front()`                                    O(1)
  `back()`                                     O(1)
  `data()`                                     O(1)
  `size()`                                     O(1)
  `capacity()`                                 O(1)
  `empty()`                                    O(1)
  `max_size()`                                 O(1)
  `reserve()`           O(n) if reallocation occurs
  `resize()`                                   O(n)
  `shrink_to_fit()`     O(n) if reallocation occurs

------------------------------------------------------------------------

# Best Practices

-   Use `operator[]` only when the index is guaranteed valid.
-   Use `at()` for safer access.
-   Use `reserve()` when the approximate number of elements is known.
-   Avoid relying on a specific capacity growth factor.
-   Remember that reallocation invalidates iterators, pointers and
    references.
-   Use `data()` when interoperating with C libraries.

------------------------------------------------------------------------

# Interview Questions

### What is the difference between `size()` and `capacity()`?

``` text
size()     -> Current number of elements.
capacity() -> Allocated storage before reallocation.
```

------------------------------------------------------------------------

### Does `reserve()` change the size?

``` text
No.
```

------------------------------------------------------------------------

### Does `resize()` change the capacity?

``` text
It may increase capacity if needed, but reducing size does not necessarily reduce capacity.
```

------------------------------------------------------------------------

### Does `clear()` free memory?

``` text
No. It removes elements but usually keeps the allocated capacity.
```

------------------------------------------------------------------------

### What does `data()` return?

``` text
A pointer to the first element of the contiguous storage.
```

------------------------------------------------------------------------

# Summary

``` text
Element Access : [], at(), front(), back(), data()

Capacity APIs  : size(), capacity(), empty(), max_size()

Memory APIs    : reserve(), resize(), shrink_to_fit()

Important      : reserve() changes capacity only

Important      : resize() changes logical size

Storage        : Contiguous

Reallocation   : Invalidates pointers, references and iterators
```
